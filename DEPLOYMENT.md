# Deployment Guide: Render & Supabase

This guide outlines deploying the **Triage AI Backend** on **Render** using a managed PostgreSQL database hosted on **Supabase**.

---

## 1. Set Up Database on Supabase

1. Go to [Supabase](https://supabase.com/) and sign in or create an account.
2. Click **New Project**, select an organization, name your project (e.g. `triage-ai-db`), and set a secure database password. Choose a region close to your users or close to Render's service region (e.g. `Singapore` / `ap-southeast-1` or `Frankfurt` / `Oregon`).
3. Once the database is provisioned:
   - Navigate to **Project Settings** (gear icon) > **Database**.
   - Under **Connection string**, select **URI**.
   - Choose **Connection Pooling** (recommended for cloud deployments like Render):
     - **Mode**: Select **Session** (port `5432`) or **Transaction** (port `6543`).
     - Copy the URI. It will look like:
       ```
       postgresql://postgres.[project-ref]:[YOUR-PASSWORD]@aws-0-[region].pooler.supabase.com:5432/postgres?sslmode=require
       ```
     - Replace `[YOUR-PASSWORD]` with your actual Supabase database password.
     - *Note: If your password contains special characters (`@`, `#`, `%`, `&`, etc.), URL-encode them.*
4. Tables will be automatically created by the backend on first boot via SQLAlchemy (`Base.metadata.create_all`).

## 2. Deploy Backend to Render

### Option A: Deploy via Blueprint (`render.yaml`) — Recommended

1. Push your repository to GitHub or GitLab (ensure it is private).
2. Go to your [Render Dashboard](https://dashboard.render.com/) and click **New +** > **Blueprint**.
3. Select your repository. Render will automatically parse [render.yaml](file:///C:/Users/monik/Desktop/research/render_safe/Wearable-Health-Track-Device/render.yaml).
4. Fill in the prompted environment variables:
   - `DATABASE_URL`: Paste your Supabase PostgreSQL connection URI from Step 1.
   - `ADMIN_USERNAME`: Choose an admin username (do **not** use the default `"admin"` in production).
   - `ADMIN_PASSWORD`: Choose a strong password (do **not** use `"triage2024"` in production).
   - `SECRET_KEY`: Automatically generated by Render.
   - `DEVICE_AUTH_TOKEN` & `DEVICE_HMAC_SECRET`: Automatically generated by Render.
   - `AWS_*` / `FIREBASE_*`: Fill in if soldier photos or push notifications are required, or leave blank initially.
5. Click **Apply**. Render will install dependencies and boot the server using Uvicorn.

### Option B: Deploy Manually as a Web Service

If you prefer setting up the Web Service manually in Render:
- **Environment**: Python
- **Root Directory**: `software/backend`
- **Build Command**: `pip install -r requirements.txt`
- **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`
- **Health Check Path**: `/`
- **Environment Variables**:
  - `ENVIRONMENT` = `production`
  - `DATABASE_URL` = `<your-supabase-connection-string>`
  - `ADMIN_USERNAME` = `<your-custom-admin-username>`
  - `ADMIN_PASSWORD` = `<your-secure-password>`
  - `SECRET_KEY` = `<a-random-32-byte-hex-string>`
  - `PORT` = `10000`
  - `RESET_ADMIN_PASSWORD` = `false`

## 3. Verify Deployment

1. Check the Render deployment logs. You should see:
   - Database connected
   - Admin user initialized
   - `Self-ping started`
   - `Uvicorn running on http://0.0.0.0:10000`
2. Open your Render public URL in the browser: `https://<your-service>.onrender.com/`
   - It should return:
     ```json
     {"status": "ok", "app": "Triage AI Backend", "environment": "production"}
     ```
3. Verify the database tables in Supabase:
   - In Supabase, open the **Table Editor**. You should see tables: `squads`, `soldiers`, `vitals`, `alerts`, `locations`, `suit_configs`, `user_credentials`, `esp32_devices`.

## 4. Enable Supabase Row Level Security (RLS) & Policies

To protect your Supabase database against unauthorized public API access (via Supabase's auto-generated PostgREST endpoints) while ensuring the FastAPI backend continues to operate with full access:

1. In your Supabase Dashboard, open the **SQL Editor**.
2. Open and copy the SQL statements from [`software/backend/deploy/supabase_rls.sql`](software/backend/deploy/supabase_rls.sql).
3. Paste into the SQL Editor and click **Run**.
4. **Why this won't break your existing app:**
   - The FastAPI backend connects to Supabase via SQLAlchemy using the database owner role (`postgres`). In PostgreSQL, table owners **bypass RLS by default** (unless forced), so all backend queries, background tasks, and WebSocket updates continue to work seamlessly.
   - `service_role` (used for administrative tasks and Supabase Edge Functions) is granted full access.
   - Credential tables (`admin_credentials`, `user_credentials`) are strictly sealed off from public/anon/authenticated PostgREST queries.
   - Operational tables (`soldiers`, `vitals`, `alerts`, etc.) permit authenticated read access while blocking unverified external writes.

## 5. Recovering Admin Password without Shell Access

If you ever need to reset the admin password on Render:
1. In Render Dashboard > **Environment**, set `RESET_ADMIN_PASSWORD=true`.
2. Update `ADMIN_PASSWORD` to your new password.
3. Save changes and deploy. The backend will update the admin password on startup.
4. Set `RESET_ADMIN_PASSWORD=false` immediately after successful login to prevent overwriting on future restarts.

## 5. Connecting Android App & ESP32

### Android Client
1. Open `software/frontend/app/src/main/java/com/example/healthmonitor/NetworkConfig.kt`.
2. Set:
   ```kotlin
   const val USE_LOCAL_BACKEND = false
   const val PROD_HOST = "<your-service>.onrender.com" // without https://
   const val PROD_BASE_URL = "https://$PROD_HOST"
   const val PROD_WS_URL   = "wss://$PROD_HOST/ws/connect?feed=all"
   ```
3. Build and install the signed APK.

### ESP32 Wearable Device
- The ESP32 receives the backend host during BLE provisioning from the Android app.
- Once configured, it will send telemetry directly to your Render endpoint over HTTPS port 443.
